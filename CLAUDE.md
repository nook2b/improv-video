# improv-video — контекст проекта

Приложение для macOS в строке меню. Человек вставляет карту камеры Insta360 Ace Pro 2, а приложение
само собирает ролик каждого дня съёмки (цвет, звук, склейка) и выдаёт его на YouTube.

Владелец и единственный пользователь — ведущий импровизационных тренировок. Канал «Иван improv».
Пишет по-русски, не программист. Отвечать ему по-русски, простыми словами, без внутренней кухни.
Все тексты в интерфейсе — для человека, который видит приложение впервые: без отсылок к нашей
переписке, «аудиту», «новому доступу» и т. п. (см. раздел «Тексты»).

## Как работает (коротко)

1. `app/controller.py::_watch_volumes` раз в 5 с смотрит `/Volumes`. Том с `DCIM/Camera*/VID_*.mp4` — карта.
   Если идёт другая обработка: уведомление и строка «В очереди: флешка «…»» в меню.
2. `pipeline.import_card`: новые клипы (имя+размер не в журнале) → журнал. Битые клипы (нет moov) —
   пропуск со статусом `broken`. По умолчанию клипы НЕ копируются (`copy_clips=False`), читаются с карты.
3. Дни: граница 04:00 (`naming.shooting_day`). Окно «Что снимали?» (`dialogs.kind_painter`) — 4 типа
   (`naming.KINDS`: Тренировка, Занятие, Шоу, Мастер-класс) + строка «Плейлист ▾» (если вход с доступом к плейлистам).
   Окно не блокирует сборку; ответить можно позже из «Ролики».
4. `pipeline.build_day`: замер + автоцвет (`brightness.sample_frames` — до 150 кадров прыжками `-ss`,
   `autocolor.solve` — как «Авто» в Lumetri, запекается в LUT) → кодирование кусками по 5 мин параллельно
   (`video.encode_chunk`, до 4 процессов, `hevc_videotoolbox`, 10 бит, 1080p по умолчанию) → звук
   (`audio`: шумодав RNNoise «medium», loudnorm) → склейка без перекодирования.
   Порядок фильтра: fps → уменьшение до итогового размера → LUT (на 1080p в 4 раза дешевле).
5. Выдача (`controller.deliver`, свой поток, сразу после каждого дня — не ждёт всю карту):
   - ручной режим: окно «Ролик готов» (Finder + Studio + название в буфере);
   - API-режим (`upload_mode="api"`): `youtube.upload` — «по ссылке», не для детей, описание ПУСТОЕ
     (время «18:05–20:40» YouTube превращал в таймкоды), дата записи отдельным полем; затем
     `pipeline.finish_uploaded` — в плейлист дня и обложка (с повтором при сбое).
6. Автоудаление: файл ролика → Корзина через N дней (по умолчанию 3) после «Готово» или загрузки
   (`pipeline.trash_done_videos`, `done_at` в журнале).
7. «Ролики» в меню: последние 10. «×» при наведении — «Не загружать» / «Забыть день» / «Убрать»
   (`menu_model.removal`, `pipeline.discard_video`, `forget_day`, колонка `hidden`). Клипы на флешке не трогаем никогда.
8. «Собрать заново…» в меню (`controller.rebuild_day`, `State.rebuild_day`): клипы дня снова свободны, старые ролики —
   `replaced` (part = -id, скрыты); тип и плейлист дня остаются. Если флешка с клипами вставлена — сразу в очередь,
   иначе соберётся при вставке. Повторная загрузка на YouTube — новым видео (старое удаляет пользователь).

## Файлы

- `improv_video/` — ядро без интерфейса: `pipeline.py` (всё вместе), `video.py`, `audio.py`, `brightness.py`,
  `autocolor.py`, `lut.py`, `probe.py`, `scan.py`, `grouping.py`, `naming.py`, `state.py` (SQLite-журнал
  `archive/state.sqlite`, миграции в `State._migrate`), `progress.py` (этапы, «осталось», `StallWatch`),
  `youtube.py` (вход, загрузка, плейлисты, обложки, `FileTokenStore`), `tools.py` (запуск ffmpeg, отмена),
  `bench.py` (`--bench`), `selftest.py` (`--selftest` в CI).
- `improv_video/app/` — интерфейс на rumps/PyObjC: `menubar.py` (меню, обновления), `controller.py`
  (очередь задач, флешки, выдача), `menu_model.py` (чистые модели меню — тестируются), `views.py`
  (нарисованные блоки меню), `dialogs.py` (свои окна на `Canvas`), `macos.py` (osascript, Корзина, автозапуск),
  `config.py` (`~/Library/Application Support/improv-video/config.json`), `updater.py` (автообновление).
- `packaging/` — PyInstaller (`improv-video.spec`, версия там же), `icon/` (значок: `make_icon.py` из `source.png`).
- `.github/workflows/build-mac.yml` — тесты на Ubuntu, сборка .app на macOS-15 (ffmpeg + dylibbundler,
  DeepFilterNet, ad-hoc подпись), самопроверка, картинки окон в лог, **релиз `vX.Y.Z` на первый пуш новой версии**.
- `calibration/` — LUT I-Log → Rec.709 и референс; `site/` — страницы для Google OAuth (главная, политика).
- Журнал приложения: `~/Library/Logs/improv-video.log`. Токен YouTube: `Application Support/improv-video/youtube-token.json` (600).

## Выпуск версии — каждый раз

1. Поднять версию в ТРЁХ местах: `improv_video/__init__.py`, `pyproject.toml`, `packaging/improv-video.spec`
   (`sed -i 's/0\.1\.N/0.1.N+1/' …`). Текущая — см. `improv_video/__init__.py` (на момент записи 0.1.28).
2. `python3 -m pytest -q tests` (нужен ffmpeg; ~1.5 мин). `python3 -m pyflakes` на изменённых файлах.
3. Коммит по-русски: заголовок + что и почему; push в рабочую ветку.
4. CI сам выкладывает релиз; приложение у пользователя обновится само (проверка через минуту после запуска
   и раз в 6 ч, ставится когда ничего не обрабатывается). Ждать CI: опрос
   `https://api.github.com/repos/nook2b/improv-video/actions/runs?branch=<ветка>&per_page=1` (публичный).
5. Картинки окон из CI: лог job `mac` → строки `PNG <имя>-light.png <base64>` (через
   `mcp__github__get_job_logs`, результат сохраняется в файл — достать regex'ом и посмотреть).

**Перед выпуском проверить, что номер свободен**: `curl -s https://api.github.com/repos/nook2b/improv-video/releases/latest`.
Параллельные сессии в других ветках тоже выпускают версии; если номер занят, CI молча (с предупреждением)
не выпускает — так 16.11.2026 «Собрать заново…» не дошло до пользователя (0.1.27 выпустила ветка
`claude/charming-fermi-y7uuzh`; влита, вышло как 0.1.28). Чужие ветки `claude/*` с новыми коммитами — вливать.

Рабочая ветка последних сессий: `claude/kind-gates-5y7myi`. Она НЕ влита в `main` (main отстаёт на ~30 коммитов).
Релизы делаются с любой ветки `claude/**`, поэтому пользователь получает их и так. Перед новой работой —
продолжать от последней ветки (или влить в main по просьбе пользователя).

## Окружение пользователя

- MacBook на Apple Silicon (видеочип расшифровывает 4K ~100–135 к/с — это потолок скорости), мало места
  на диске (~90 ГБ доступно с учётом освобождаемого; `pipeline.free_bytes` считает как «Хранилище» macOS).
- Карта Samsung PRO Plus 256 ГБ (UHS-I, A2) через переходник в слот SD Mac — не узкое место.
- Камера пишет 4K, ~94 Мбит/с; день 1–5 ч видео. Реальная скорость сборки 1080p ≈ ×1.8 от реального времени.
- YouTube: вход через свой OAuth-клиент (client_secret.json). Google ответил, что загрузки через API
  не делаются приватными автоматически. Пользователь включил «автоматически». Для плейлистов и обложек
  нужен scope `youtube` (вход до 0.1.21 — только `youtube.upload`, меню предлагает «Войти заново…»).
- Плейлисты у него по КОМАНДАМ (в одном плейлисте и тренировки, и занятия, и шоу), мастер-классы — свой плейлист.

## Решения, которые уже приняты (не переделывать без просьбы)

- scale_vt (уменьшение на видеочипе) медленнее процессора — не использовать.
- 4 куска параллельно; звук считается после видео (идея считать параллельно — не сделана).
- Описание ролика пустое. Названия: «Тип ДД.ММ.ГГГГ», «… (часть 2)».
- Расшифровку речи/оглавления не делаем — пользователь пробует автоматические главы YouTube в Studio.
- Токен в файле, а не в Keychain (иначе пароль Mac после каждого обновления из-за ad-hoc подписи).
- Архив нельзя класть на карту камеры (`pipeline.is_camera_card`; при запуске возвращается в ~/Movies).
- Уведомления через osascript ненадёжны — важное показывать в меню (блок вверху) или окном.

## Тексты

Всё, что видит человек, — полными простыми фразами. Нельзя: «вход с новым доступом», «до аудита API»,
«этот проект», «при вставке» как кнопка, английские статусы (`private` → «Ограниченный доступ»,
`youtube.PRIVACY_RU`). Технические строки журнала (скорость кусков `×N`, «Нет прогресса … источник: 8 МБ за …»)
можно оставлять — они для разбора проблем.

## Тестирование

- Всё, что не требует AppKit, покрыто pytest (контроллер — с `FakeUI` в `tests/test_controller.py`,
  YouTube — с поддельным service). AppKit-код (окна, меню, перетаскивание) на Linux не запускается:
  проверять по картинкам из CI и честно говорить пользователю, что на живом Mac не проверено.
- Песочница: прокси с собственным CA — запросы к GitHub из Python падают на сертификате, это нормально;
  developers.google.com закрыт.
- CI-тесты закреплены на `ubuntu-24.04`. С новым ffmpeg (Ubuntu 26, brew на Mac) метки BT.709 терялись;
  исправлено в `video.py` (метки ставятся на кадры, коммит eb79f55). Самопроверка сборки на Mac печатает
  «пометки цвета: …» — в логе job `mac` должны быть все четыре (primaries, transfer, space, range).

## Открытые идеи (не начаты)

- Считать звук одновременно с кодированием (−7 мин на день).
- Почистить старые описания у уже загруженных роликов через API.
- Копировать клипы на Mac по одному дню (если окажется, что тормозит флешка).
- Постоянный сертификат подписи (Apple Developer) — убрал бы повторные запросы разрешений macOS.
